## Overview

Redesigned the core flows and information architecture of a lottery entertainment app — turning a high information-density, transaction-heavy interface into a clearer, faster, and more understandable mobile experience.

---

## Scope of Work

Mobile UX · Information Architecture · User Flow · Core Task Flow · UI Design · Design Library · Interaction Design · Design Handoff

---

## The Challenge

Lottery App is a mobile product with multiple game types and high-frequency operational needs. The original interface carried a large amount of information and features, but its flows were cumbersome — users easily felt burdened when finding games, understanding rules, and completing core tasks.

The core challenge of this project was this: how to reduce mobile operational complexity while keeping the full feature set, and let both new and experienced users complete tasks effectively.

### Core Pain Points

- The core flows were long, requiring users to switch between multiple pages and confirmation states.
- The information hierarchy across game types was unclear, making it hard for users to quickly find their frequently used items.
- High information density on pages meant new users needed more time to understand the interface and how to operate it.
- Different game types lacked consistency in visuals and interaction patterns, undermining the overall product experience.

---

## Design Process

I was responsible for restructuring the mobile UX flows, optimizing the information architecture, designing the core operational interfaces, establishing the visual system, and planning the Design Library. Throughout the process, I focused on lowering the cost of repeated actions, improving information legibility, and building a consistent experience across game types.

---

## Design Strategy

### Reorganizing User Tasks & Information Architecture

I first analyzed users' main behaviors in the product, splitting "frequently used items" and "exploring other items" into different levels. For experienced users, this means returning to common actions faster; for new users, clear categorization helps them understand the product's content.

This information architecture supports both high-frequency use and newcomer exploration, without cramming everything into a single entry point.

### Simplifying the Core Flows

I redesigned the core flows to cut unnecessary page jumps and repeated confirmations, letting users complete their main tasks more directly. For highly repetitive actions, I also designed quick selections and default states to reduce the burden of reconfiguring everything each time.

The point of this strategy wasn't simply to remove screens, but to make every step better fit the user's operational intent.

### Building a Consistent Visual & Component System

Since the product includes multiple game types, I built a consistent Design Library that unifies colors, icons, buttons, cards, status cues, and operational components. Users can quickly identify content types through consistent visual rules, and keep a familiar feel when moving between different games.

### Lowering the Learning Cost for New Users

For information-dense pages, I re-prioritized the information, presenting primary actions, supporting information, and rule explanations in layers. Users can complete the core task first and then view advanced information as needed, avoiding being overwhelmed by too much content from the start.

---

## Impact

- Reorganized the core flows so users can complete their main tasks more directly.
- Optimized the information architecture across game types, improving the clarity of finding and identifying content.
- Established a consistent Design Library, letting future features and new game types extend in a more stable way.
