## The Challenge

66 Chat is an enterprise communication platform serving diverse user roles — from frontline employees to department managers and system administrators — while offering customizable business upgrade paths for different organizational needs. The core challenge was balancing "complex feature depth (multi-role permissions, group broadcasts, customizable modules)" with "a minimal, intuitive experience" across desktop and mobile.

### Core Pain Points

- Multiple user roles (employee, manager, admin) required distinct interfaces and permissions, but fragmented experiences across roles led to confusion and repeated support tickets
- Businesses needed customizable upgrade options (advanced group management, analytics dashboards, branded themes) but the upgrade flow was buried and unclear — only 8% of trial users discovered premium features
- Multi-level contact classification (new friends, groups, labels) created navigation paths 4+ levels deep
- The platform needed to convey enterprise-grade security trust while remaining comfortable for 8+ hours of daily use

---

## Design Strategy

### 1. Multi-Role Permission Architecture

Designed a role-based UI system where each user type sees a tailored interface. Employees get a streamlined chat-focused view, managers access team oversight and broadcast tools, and admins control organization-wide settings and user management. A unified navigation framework ensures seamless role switching without losing context.

The key was **progressive disclosure** — rather than hiding features behind role gates, the interface adapts subtly. A manager sees the same conversation list as an employee, plus a team analytics tab. An admin sees both, plus a settings panel. The cognitive load stays low because the foundation is familiar at every level.

### 2. Business Customization & Upgrade Module

Created a progressive upgrade experience that surfaces premium features naturally within daily workflows. For example: when a manager creates a group and hits the 50-member limit, instead of a generic error, they see a preview of the expanded group with 200+ slots, sample analytics charts, and a one-click upgrade path — all within the same modal.

The modular design allows businesses to select only what they need: advanced group management, custom branding, API integrations, or analytics dashboards. Each module shows a **live preview with sample data** before purchase, so decision-makers can evaluate real value rather than reading feature descriptions.


---

## Key Design Decision

For the multi-role system, I faced a critical choice: **"Single app with role-based views"** vs. **"Separate apps per role."**

I chose the single-app approach with adaptive UI — the navigation structure stays consistent, but content panels, action buttons, and feature access dynamically adjust based on the user's role. This decision reduced onboarding friction dramatically: users promoted from employee to manager didn't need to learn a new interface. Role-specific features are progressively revealed through contextual permission layers rather than hidden behind separate entry points.

For the business upgrade module, I designed a **"Try before you buy"** pattern — premium features show interactive preview states with sample data, so decision-makers can evaluate value before committing. This replaced the traditional feature-gated lockout screens that had been causing 73% drop-off at the upgrade page.

## Impact

- Multi-role permission system reduced admin configuration time by 60% compared to the previous flat-permission model
- Contextual upgrade touchpoints lifted business plan conversion rate from 8% to 24% — a 3x improvement over the traditional pricing page
- Flattened navigation structure reduced average path depth from 4+ levels to 2, cutting task completion time by 40%
- Premium minimal UI helped organizations achieve 89% employee adoption rate within the first month of rollout
