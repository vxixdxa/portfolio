## Overview

Replanned the back-office management system for an esports gaming company — integrating cross-department workflows, data monitoring, management tools, and a design system to improve the backoffice product's consistency, usability, and efficiency of future expansion.

---

## Scope of Work

UX Architecture · User Role Analysis · Dashboard Design · Information Architecture · UI Design · Design System · Component Library · Design Guideline · Design Handoff

---

## The Challenge

IM ESports Backoffice is a back-office management system used by multiple internal departments, with users spanning business analysis, operations, customer service, and management. As features accumulated over time, the original system developed inconsistent interaction logic, scattered page information, and non-unified visual standards — forcing users to spend considerable learning effort to find data and complete tasks.

The core challenge of this project was this: how to reorganize a complex backoffice architecture without disrupting existing workflows, and establish a design system that can be maintained and extended over the long term.

### Core Pain Points

- Workflows and page logic differed across departments, so users easily got confused when operating across functions.
- The backoffice carried a large volume of data and management features with unclear information priority, hurting the efficiency of finding information and making decisions.
- The lack of a unified design language meant interface quality and interaction patterns were inconsistent whenever new features were added.
- The legacy system had long been in daily use by the team, so a redesign had to balance migration cost against established usage habits.

---

## Design Process

I was responsible for the backoffice product's UX architecture, role-and-task mapping, dashboard interface design, component system, design specifications, and handoff documentation. Throughout the process, I worked with product team members to map out the workflows of different roles, organizing recurring interaction patterns into reusable design components.

---

## Design Strategy

### Mapping User Roles & Task Flows

I started from the usage scenarios of different departments, mapping out each role's main tasks, operational paths, and common breakpoints in the backoffice. Through role and flow mapping, I could more clearly judge which information should take priority and which operations needed to be simplified or unified.

This made the design about solving problems within real workflows, not just repackaging the interface.

### Building a Role-Oriented Dashboard Architecture

Backoffice users don't need to see all the data — they need to quickly find the information relevant to their own tasks. So I shifted the dashboard from a single overview-style interface to an information architecture closer to each role's tasks.

After logging in, different roles first see the metrics, statuses, and entry points relevant to their work, reducing the burden of searching through large volumes of information.

### Building a Scalable Design System

To solve interface inconsistency and the difficulty of maintaining future features, I built a componentized UI architecture and design specifications — including tables, filters, status labels, action buttons, forms, notification messages, and common backoffice components.

Through unified components and rules, different functional modules can maintain consistent interaction patterns, while also lowering the communication cost of subsequent design and development.

### Adopting a Progressive Redesign Strategy

Because the backoffice is a core daily tool for internal teams, I avoided overhauling all flows at once and instead adopted a progressive rollout. I unified the visuals and base components first, then gradually adjusted key flows and information architecture, letting users adapt to the new interface on a familiar foundation.

---

## Impact

- Reorganized the backoffice information architecture so different roles can more clearly find content relevant to their own tasks.
- Established a consistent design language and component system, improving the efficiency of future feature extension and cross-team collaboration.
- Lowered users' adaptation cost through a progressive redesign, letting the new interface roll into daily workflows more smoothly.
- Turned long-accumulated backoffice features into a clearer, more stable, and maintainable product architecture.
